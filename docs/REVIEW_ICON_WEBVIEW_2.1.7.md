## 建议接着处理的优化

1. **优先保护收藏数据。** `PreferencesRepository.parseFavorites()` 在 JSON 损坏时返回空列表；随后增删会以这个空列表为基础写回，可能覆盖仍可恢复的原始数据。建议保留损坏副本、拒绝破坏性写回并显示恢复提示，增加损坏数据回归测试。本轮没有改变收藏存储格式。
2. **增加可见的运行诊断。** 管理界面仍难以说明各 ROM 的定位适配器实际安装状态；地图凭据解密失败也会退回空值。建议分别显示可恢复错误和适配失败项，避免将配置问题误判为整个模块失效。
3. **验证连续运行与生命周期。** 补充 Mock Provider 重建、熄屏/恢复、快速启停和离线设置同步测试，并覆盖 Android 11–16 的 AOSP 与 OEM 系统。系统 Hook 不应仅凭版本范围称为已实测。
4. **测量后再优化队列与地图契约。** 设置保存使用无限串行队列；长时间阻塞可造成积压。先增加可观测的队列等待时间，再考虑合并重复选点、超时和恢复策略，保留不可丢失的启停操作。地图供应商的共同行为可抽成契约测试，减少三个 HTML 实现漂移。

上述建议依据代码路径与测试覆盖范围，未将尚未复现的后果描述为当前手机已发生故障。
