# 2.1.3-rc1 审查整改与验收

本批以 2.1.2 (`47c4efd`) 为基线，优先处理审查 #1、#2、#4、#5、#6、#19、#20、#25，并完成相关 Root 和配置安全加固。不是对全部 28 项问题已经解决的声明。

## 本批改动

- #1：联合申请精确和粗略位置，接受粗略权限；从设置返回时重新检查。
- #2：系统 Binder 与两类 Transport 适配器独立安装。Android 11 不再允许新选用全局系统模式，仍保留应用模式和 Mock Provider。
- #4：应用 listener 按对象身份和 provider 管理；重新注册更新参数；原生与补发共用请求次数、间隔、最小距离和期限。单次 current-location 保留原生权限、取消与返回流程。未明确识别的请求不主动补发。
- #5：管理界面统一读取本地缓存；离线修改持久化待同步键，连接时保留远端旧设置并合并本地修改；删除不会被远端旧值恢复。地图凭据不进入远程配置。
- #6：Mock Provider 区分启动中、运行、失败；仅成功注入后显示运行，失败取消模拟请求并提示。配置提交在后台串行执行。
- #19：新增 NMEA、原始测量和导航电文的系统侧回调保护；仅对第三方注册、系统模拟期间拦截原始事件，保留原生注册检查和状态回调。需要逐 ROM 验证接口是否成功 Hook；不能据此宣称所有定位通道均已覆盖。
- #20：区分普通 Wi-Fi 扫描列表与 ParceledListSlice；不再因包装失败放行原始扫描结果。
- #25/#23：发布前执行测试、Lint、签名指纹和非调试检查；输入通过环境变量传递，仅上传到草稿，禁止覆盖同名资源。
- #18：Root 命令仅允许已安装列表中的合法包名，输出直接丢弃，等待有超时，失败销毁子进程。
- #22：保留已有外部自动化用途；接收时再次检查开关，拒绝无效 START 坐标。未引入 signature 权限，因此用户显式开启外部控制后仍允许其他应用调用。
- 附带修复：Mock 服务使用串行 provider 清理；排除管理应用的系统位置查询；收藏位置不再写日志；搜索输入变化清除旧 loading；更正签名文档。

## 实机验收

1. 原测试机安装 rc1 后重启；保留三个系统组件，系统定位关闭、模拟开启，验证微信、企业微信及高德地图。
2. 再开启系统定位，确认位置没有变回真实位置；停止模拟后确认系统定位行为恢复。
3. 应用模式分别测试单次、重复定位；到期/取消后确认没有多余回调。暂不修改支付宝适配。
4. Mock Provider 测试：正确授权时启动；撤销模拟位置授权且拒绝 Root 后应提示失败；快速开始/停止后不应残留 provider。
5. LSPosed 不可用时保存坐标，退出重进；重新连接 LSPosed 后核对坐标、模式和旧配置。
6. 新装/撤销权限后测试“仅粗略位置”，再去系统设置授权返回。
7. 使用测试客户端在模拟开始前后订阅 NMEA/原始 GNSS 数据；确认系统日志报告所需适配器已安装且模拟期间没有原始事件。原始通道和 ROM 兼容性验证未完成前不发布正式版。

测试包与正式版使用相同用户自持签名，版本号为 2.1.3-rc1。这里的构建版本与 API 的回调行为仍需实机验证，单元测试不能代替 LSPosed 运行测试。
