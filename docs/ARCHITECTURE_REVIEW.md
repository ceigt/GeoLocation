# 2.0 后续架构复核（尚未发布）

## 对比范围

原版参考文件为 LocusMimic 2.0.2（标签 `20002-2.0.2`），散列及初次分析见 [V2_REVIEW.md](V2_REVIEW.md)。复核了反编译的 ModuleEntry 和部分 LocationApiHooks 调度；部分方法未成功还原，没有完整审计。没有复制反编译代码或分析订阅绕过。

两者模块入口都继承 libxposed 的 XposedModule，运行在 LSPosed 提供的环境中，因此不能把兼容性差异归因于“使用了更好的框架”。

| 维度 | 判断及证据限制 |
| --- | --- |
| 适配覆盖 | 原版静态可见独立高德等通道，GeoLocation 当前主要为 Android 接口与腾讯标准/sapp 适配。原版可见覆盖更广，但没有同设备、同版本、同配置的完整对照实测。 |
| 可维护性 | GeoLocation 源码和构建可控；应用适配已拆分。系统服务适配仍较集中，后续可按系统版本和厂商拆分，不能称为架构全面领先。闭源 APK 的反编译组织也不能代表作者的原始项目结构。 |
| 初始化稳定性 | 原版入口对立即安装与 Instrumentation 登记分别捕获异常。GeoLocation 2.0 对方法查找有保护，但登记动作不在同一保护范围内；本轮补齐。 |
| 隐私与安全 | GeoLocation 由用户自备地图凭据，无订阅授权服务；本轮补充系统云备份及换机迁移排除规则。这些是隐私控制，不是无法检测的保证。 |
| 性能与定位正确性 | 没有统一基准、耗电数据或真机回归结果，不下“更快、更准、更隐蔽”的结论。 |

## 本轮修改

- 应用适配构造、Instrumentation 方法查找与登记分别隔离失败；单个可选适配异常不会阻止后续安装。
- 系统最后位置、当前请求、持续派发、MIUI 适配分别隔离安装失败。日志不再无条件宣称所有 Hook 安装成功。
- 共用异常边界处理普通异常与 LinkageError，保留 OutOfMemoryError 等虚拟机致命错误的传播，不吞掉所有 Throwable。
- 新增三个测试验证后续适配继续执行、SDK 链接失败被报告、虚拟机致命错误不被吞掉。测试仅覆盖异常边界，不证明设备端 Hook 安装成功。
- Android 12+ 显式排除云备份和设备迁移中的应用数据，避免只设置 allowBackup=false 时部分厂商仍迁移地图凭据。此规则不控制 root 备份工具或 LSPosed 自身的远程配置存储。依据：[Android 官方备份说明](https://developer.android.com/identity/data/autobackup)。

以上是 2.0 后续源码改动；已发布的 `20000-2.0.0` APK 不会被静默替换。正式版本仍需对应的新构建与真机回归。
